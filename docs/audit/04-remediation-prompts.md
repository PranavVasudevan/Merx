# BankLens — Remediation Prompts

One ready-to-paste prompt per issue in `03-issue-register.md`. Each is self-contained:
it names the files, states the constraint, and gives acceptance criteria.

**Global constraints to keep in mind for every prompt below** (repeat them if you paste
a prompt into a fresh session): *the project has a hard $0 spend rule; no synthetic or
sample data anywhere; every derived number must come from the Gold layer, computed
once; connectors stay stdlib-only where they already are; anything that cannot be
verified must be disclosed rather than guessed.*

---

## A · Deployability, hosting and $0-cost fit

### A1 — Make the API base URL configurable
> In `frontend/apps/web/src/api.ts`, `BASE` is hardcoded to `http://localhost:8791/api`, which makes the app undeployable. Replace it with `import.meta.env.VITE_API_BASE ?? 'http://localhost:8791/api'`, following the exact pattern already used for `VITE_KEYCLOAK_URL` in `src/auth.ts`. Add a `.env.example` in `frontend/apps/web/` documenting both variables, add `VITE_API_BASE` as a build arg in `frontend/apps/web/Dockerfile`, and delete the now-obsolete "honest local-only note" comment block in that Dockerfile once it is no longer true. Acceptance: `VITE_API_BASE=https://api.example.com npm run build` produces a bundle that calls that host, and the default dev build is unchanged.

### A2 — Make CORS origins configurable
> In `services/api-gateway/src/bridge_server.py`, `_ALLOWED_ORIGINS` is a hardcoded set of three localhost ports. Read it from a `BANKLENS_ALLOWED_ORIGINS` env var (comma-separated), falling back to the current three values so local dev is unchanged. Keep the existing echo-back-only-on-match behaviour and the comment explaining why `*` is unacceptable. Document the variable in `.env.example`. Acceptance: a deployed origin passed via the env var receives the `Access-Control-Allow-Origin` header; an unlisted origin still receives none.

### A3 — Decouple auth from self-hosted Keycloak
> `frontend/apps/web/src/auth.ts` hardcodes the realm (`banklens`) and client (`banklens-web`), and `services/api-gateway/src/auth.py` defaults `KEYCLOAK_ISSUER` to a localhost Keycloak. Generalise both to any standards-compliant OIDC provider: frontend reads `VITE_OIDC_AUTHORITY` / `VITE_OIDC_CLIENT_ID`; the bridge reads `OIDC_ISSUER` and derives the JWKS URL from the provider's `/.well-known/openid-configuration` rather than assuming Keycloak's `/protocol/openid-connect/certs` path. Roles must still come from the access token, but the claim path should be configurable (`OIDC_ROLES_CLAIM`, defaulting to `realm_access.roles`) so Auth0/Clerk/Supabase free tiers work. Keep Keycloak working unchanged as the local-dev default. Acceptance: the bridge validates a token from a non-Keycloak OIDC provider and extracts roles from a configured claim path.

### A4 — Add a production-safe server mode to the bridge
> `services/api-gateway/src/bridge_server.py` uses `ThreadingHTTPServer` with no request timeout, no body-size limit, no rate limit and unbounded thread creation. Keep that path for local dev, but add a deployment path: a `--server=prod` mode (or a `BANKLENS_SERVER=prod` env var) that serves the same `ROUTES`/`POST_ROUTES`/`DELETE_ROUTES` tables through a WSGI app behind gunicorn with a bounded worker/thread pool, a 30s default request timeout, a 1 MB request-body cap, and a simple token-bucket rate limit per subject claim. Do not duplicate any routing or business logic — factor the dispatch into a shared function both modes call. Add the pinned dependency to the Dockerfile. Acceptance: both modes serve identical responses for every route; the prod mode rejects an oversized body with 413 and a flood with 429.

### A5 — Ship the Gold layer as a single queryable artifact
> Today the bridge reads ~96 MB of Bronze JSON from a mounted `data/` directory (`services/mcp-server/src/banklens_mcp/data.py`), which no free host can persist. Add a build step (a new CLI in `pipelines/transforms/`) that materialises the computed Gold layer — all landed quarters, plus footprints, county table, crosswalk and cluster assignments — into a single DuckDB file, and teach `data.py` to load from that file when `BANKLENS_GOLD_DB` is set, falling back to the current JSON path otherwise. The DuckDB file must be reproducible from Bronze and must carry a provenance table recording which Bronze partitions and checksums produced it. Acceptance: the bridge serves every route identically from the DuckDB artifact with `data/bronze/` absent, and the artifact is under 50 MB.

### A6 — Cut bridge memory below 512 MB
> Measure and reduce the bridge's resident memory. Current hot spots in `services/mcp-server/src/banklens_mcp/data.py`: `sod_raw()` loads all 76,120 SOD branch rows into Python dicts; `population()` is cached per quarter for all 8 quarters; `duckdb_gold()` round-trips the whole Gold layer through a temporary NDJSON file. Fix by (a) querying SOD from the DuckDB artifact from A5 instead of holding it in memory, (b) bounding the per-quarter population cache to the 2 most recent quarters with an LRU for the rest, and (c) removing the NDJSON round-trip now that DuckDB owns the data. Report before/after RSS in the PR. Acceptance: steady-state RSS under 400 MB with all routes exercised.

### A7 — Default the assistant to a free hosted provider when Ollama is absent
> `services/agents/src/banklens_agents/providers.py` defaults to Ollama, which cannot run on free hosting. Add provider auto-detection: if `BANKLENS_LLM_PROVIDER` is unset, probe `OLLAMA_HOST` with a short timeout and use Ollama if reachable; otherwise fall back to Gemini using the multi-key rotation already implemented in `gemini_keys.py`; if neither is available, return a clear, actionable error instead of hanging. Keep the explicit-override behaviour and the $0 rule intact — never fall back to Anthropic automatically. Acceptance: with no Ollama running and `GEMINI_API_KEY` set, `/api/assistant/ask` answers successfully and the response reports which provider served it.

### A8 — Support `DATABASE_URL` for free Postgres tiers
> `libs/python/banklens_common/src/banklens_common/db.py` builds its connection from `POSTGRES_HOST/PORT/USER/PASSWORD/DB` only, so Neon and Supabase free tiers (which issue a connection string and require `sslmode=require`) cannot be used. Accept a `DATABASE_URL` env var that takes precedence over the discrete variables, pass it straight to `psycopg.connect`, and keep the existing fail-open behaviour when the DB is unreachable. Verify pgvector extension creation works on a hosted instance where the app user is not a superuser. Acceptance: the audit-log, agent-run, watchlist and filing-chunk round-trip tests pass against a free hosted Postgres using only `DATABASE_URL`.

### A9 — Remove unused infrastructure from the dev compose stack
> `platform/docker/docker-compose.dev.yml` runs ClickHouse, MinIO and Redis. Grep the whole repo and confirm no application code references any of them, then delete those three services, their volumes, and their env vars from `.env.example`. If they are genuinely part of a future plan, move them to a clearly-labelled `platform/docker/docker-compose.future.yml` that is not referenced by any script. Update `README.md`'s tech-stack table, which currently lists databases that nothing connects to. Acceptance: `docker compose -f docker-compose.dev.yml up` starts in noticeably less time and memory, and CI's compose validation still passes.

### A10 — Fail loudly when the refresh job has no durable volume
> `platform/k8s/base/refresh-cronjob.yaml` mounts an `emptyDir`, so a refresh that runs without the dev/prod overlay patch writes a full population land into scratch space that vanishes. Add an init container (or a startup assertion in `quarterly_refresh.py`) that verifies the data mount is backed by a PVC and is writable, and fails the job with a clear message otherwise. Also add a post-run assertion that the expected partitions exist on disk. Acceptance: running the base manifest without an overlay fails fast with an explanatory message instead of silently succeeding.

### A11 — Add a static-hosting deployment path for the frontend
> The only frontend artifact today is an nginx container. Add a free-tier static deployment: a Cloudflare Pages (or Netlify) configuration plus a GitHub Actions job that builds `frontend/apps/web` with `VITE_API_BASE` and `VITE_OIDC_*` injected from repository variables and publishes `dist/`. Include the SPA fallback rewrite so client-side routes resolve, and the security headers currently set in `nginx.conf`. Acceptance: a push to `main` publishes a working static site whose routes deep-link correctly.

### A12 — Make market-data landing budget-aware
> `pipelines/ingestion/src/banklens_ingestion/market_cli.py` takes a `limit` but has no awareness of Tiingo's free-tier ceiling (250 calls/day, 50 symbols/hour). Add a persistent cursor so successive runs round-robin through the crosswalk-matched ticker universe rather than always re-landing the same head, a rate limiter that respects the hourly ceiling, and a coverage record (tickers landed / tickers eligible / oldest bar age). Surface that coverage through a new MCP tool and show it on the bank page's price chart when data is stale or absent. Acceptance: repeated daily runs monotonically increase ticker coverage without exceeding the free-tier limits.

## B · Data coverage and sourcing

### B1 — Backfill 20 quarters of population history
> Only 8 quarters (2024Q2–2026Q1) are landed, which makes `growth_rate_3yr_pct` and `deposit_growth_rate_3yr_pct` always `None` and forces `deposit_growth_1yr` — the highest-weighted deposit-flight feature — to be imputed on every score. Use `population_land_cli.recent_quarters` to land back to 2021Q1 (20 quarters, ~2.3 MB each). Then verify: the 3-year CAGR fields become non-null for banks with continuous history; `get_risk_score` stops imputing growth; `filing_diff` z-scores are computed from a materially larger sample. Update the "growth feature imputed" caveat text in `tools.get_risk_score`/`get_risk_leaderboard` to reflect reality once it is no longer true. Acceptance: report the before/after non-null rate for each affected field and the change in the deposit-flight model card's AUC.

### B2 — Extract what EBA does publish on credit risk
> `config/sources.yaml` notes that EBA's `tr_cre.csv` (exposure-class × NACE-sector × performing-status) is deliberately unparsed because it needs the SDD.xlsx data dictionary. Land the dictionary, parse the cube, and add whatever genuinely maps to the Silver schema — at minimum an NPL ratio and a sector-concentration proxy for EU banks. Do not invent fields EBA does not publish. Where a US field has no EU equivalent, keep it `None` and extend the existing `legs_not_applied` / `rules_not_evaluated` disclosure so EU banks are visibly under-covered rather than silently averaged. Acceptance: EU banks gain real credit-risk metrics and the X-Ray's `fully_assessed` flag correctly reflects the improved-but-still-partial coverage.

### B3 — Widen the population beyond $1B–$250B
> The analytical slice excludes the four GSIBs and every bank under $1B, which is the first thing a banker notices. Extend the landing and the Gold layer to cover the full FDIC universe, but keep band structure explicit: add an `asset_band` field, compute peer percentiles **within band** as well as globally, and label every population-wide figure with the band it covers. Audit every hardcoded "$1B-$250B" string in `tools.py`, `personas.py`, and the frontend and make them derive from the actual landed band. Watch the O(n²) hot paths flagged in F8 — this change takes the population from ~1,049 to ~4,500. Acceptance: the screener covers the full universe, percentiles are band-aware, and no page still asserts a band the data no longer matches.

### B4 — Land Federal Reserve NIC holding-company data
> `config/sources.yaml` lists `fed_nic` (FR Y-9C, bulk zip, no auth) as `status: planned`. Implement the connector in `pipelines/ingestion/src/banklens_ingestion/sources/`, following the existing `fdic.py`/`eba.py` pattern (stdlib only, provenance + checksum per fetch). Join to the existing crosswalk on RSSD, add a Silver holding-company record type, and add a parent/subsidiary relationship so a bank page can roll up to its HoldCo. This is the prerequisite for M&A pro-formas and for matching tickers to the entity the market actually prices. Acceptance: a bank with a holding company shows consolidated HoldCo financials alongside its own charter-level numbers, with the source of each clearly labelled.

### B5 — Land FRED macro series
> `config/sources.yaml` lists `fred` as `status: planned`. Implement the connector (free API key, `FRED_API_KEY` already in `.env.example`) for at minimum: the Treasury yield curve (DGS3MO/2/5/10/30), Fed funds, unemployment, and the CRE price index. Land to Bronze with provenance like every other source. This unlocks scenario conditioning for the stress engine (C4/C5) and a macro context strip in the UI. Acceptance: a `/api/macro` route returns the landed series, and the stress lab can reference a real historical rate path rather than an abstract bps slider.

### B6 — Land bank failures and M&A deal history as real data
> The deposit-flight model's four positives are a hardcoded dict (`POSITIVE_CERTS` in `deposit_flight.py`) and there is no deal-comp data at all. Land the FDIC failed-bank list and FDIC BankFind institution-history events (merger/acquisition/closure) as a real Bronze source with provenance. Replace the hardcoded positives with a query over that source, keeping the documented `EXCLUDED_CANDIDATES` logic as an explicit, data-driven filter. Acceptance: the positive set is derived from landed data, the exclusion rationale is preserved, and merger events become available for validating the M&A fit weights (C9).

### B7 — Disclose SOD as-of dates alongside every footprint number
> `data/bronze/source=fdic/sod/year=2025` is the only landed SOD year, and FDIC publishes it annually — so branch counts and branch deposits are up to 18 months stale relative to 2026Q1 financials. This cannot be fixed, only disclosed. Surface the SOD vintage next to every footprint, county-HHI, market-share and branch-map figure in the UI and in the tool responses (`get_bank_profile`'s `footprint`, `get_county_concentration`, `get_branch_map`, `find_ma_matches`). The `get_county_concentration` response already carries `as_of: "SOD 2025"` — make it structural and universal rather than one string on one tool. Acceptance: no branch-derived number appears anywhere without its vintage.

### B8 — Expand SEC 10-K risk-factor coverage
> `get_filings_coverage` honestly reports a small number of landed filers. Expand `filings_cli.py` to walk the full crosswalk-matched filer universe rather than only the largest-by-assets head, with resumable state so a run can be interrupted and continued. Keep the HIGH/LOW extraction-confidence gate and keep low-confidence extractions out of the search index. Report the coverage delta. Acceptance: coverage grows materially, the coverage tool's numbers move, and no low-confidence extraction becomes searchable.

### B9 — Add point-in-time (`as_of`) querying
> FDIC restates prior quarters, but Silver/Gold always read the latest landed file, so a number shown today may silently differ from the same number shown last month. Bronze is already append-only with per-partition provenance and checksums. Add an `as_of` parameter threaded through `data.population()`, `data.bank_history()` and the tools that consume them, selecting the Bronze snapshot as of a given landing date rather than the newest. Acceptance: a query with `as_of` set to a past date reproduces the exact numbers that were served then, and the UI can show "as filed" vs "as restated".

### B10 — Expose data freshness
> Provenance (source URL, fetch timestamp, checksum) is captured in every `_provenance.json` and never surfaced. Add a `/api/data-freshness` route (and matching MCP tool) that reports, per source: the landed vintage, the fetch timestamp, the source's own publication date where known, and the expected next publication. Render it as a compact strip in `NavShell` so a user always knows how current the data is. Acceptance: every source in `config/sources.yaml` with `status: active` appears with a real, landed timestamp.

## C · Analytics and model quality

### C1 — Give the deposit-flight model honest statistics
> `pipelines/transforms/src/banklens_transforms/deposit_flight.py` trains on 4 positives and reports in-sample AUC 0.955 plus a leave-one-out over those same 4. Add, and persist into the model card: bootstrap confidence intervals for every coefficient and for AUC; a precision-recall curve evaluated at the true base rate (4 failures in ~1,655 rows); a calibration curve; and the imputation rate per feature. Do **not** claim the model is validated — the point is to show precisely how uncertain it is. Then reframe the output: rename `risk_score` in the UI to a resemblance percentile/decile rather than a percentage, since a red bar reading "62.4%" visually asserts a probability the model does not produce. Acceptance: `/model` renders the CIs, PR curve and calibration plot, and no surface presents the score as a probability of failure.

### C2 — Add hyperparameter selection and era handling to the model
> `deposit_flight.train()` uses fixed `lr=0.2, epochs=2000, l2=1.0`, mean-imputes missing features, and standardises across a pooled 2008+2022 sample despite the two eras having very different rate environments. Add a small cross-validated sweep over `l2` (still pure Python, no new dependencies), record the selected value and the sweep results in the model card, and either standardise per-era or add an explicit era indicator feature. Report whether pooling still helps once the eras are handled properly — a negative result is a valid and publishable outcome. Acceptance: the model card records the search, and the docstring's "deliberate, documented modeling choice" is backed by measured evidence rather than assertion.

### C3 — Add fixed-centroid cluster assignment
> `banklens_mcp/data.py` re-runs k-means independently for each quarter, so a bank near a boundary flips labels with a stable balance sheet — the `/trends` page already warns about this. Add a mode that fits centroids once on a chosen reference quarter, persists them, and assigns all other quarters to those fixed centroids. Serve fixed-centroid assignment for multi-quarter views (trends, briefing, migrations) while keeping per-quarter refit available and comparable on `/clusters`. When both are available, report how much of the observed "migration" is real movement versus refit noise. Acceptance: `get_quarterly_briefing`'s `cluster_migrations` reflects genuine movement, and the difference between the two methods is measured and shown.

### C4 — Make the stress engine a real stress test
> `pipelines/transforms/src/banklens_transforms/stress.py` is single-period and static: no earnings offset, no management actions, hardcoded AFS/HTM durations of 4y/6y for every bank, parallel shocks only, independent legs, and no liquidity metric. Address in this order: (1) derive per-bank securities duration from whatever maturity distribution FDIC discloses, falling back to the 4y/6y default *with that fallback flagged in the result* — this is the single largest error source; (2) add a pre-provision net revenue offset so a bank can earn through a mild shock; (3) add multi-period projection (4–8 quarters) with the shock phased in; (4) add a correlated joint-scenario mode instead of three independent sliders; (5) add a liquidity survival horizon. Preserve the byte-for-byte parity with the Rust port in `services/stress-engine` or update both together. Acceptance: every new leg is either computed from disclosed data or explicitly listed in the existing `legs_not_applied` disclosure.

### C5 — Add interest-rate risk in the banking book (EVE / ΔNII)
> Interest-rate risk is the mechanism behind the 2023 failures the product is built around, and it is not modelled. Build a repricing-gap approximation from FDIC's disclosed maturity/repricing buckets: compute economic value of equity sensitivity and a 12-month net-interest-income sensitivity under parallel shifts and at least one non-parallel scenario (steepener/flattener). Where the disclosed buckets are too coarse to be precise, say so in the result rather than smoothing over it — the same disclosure discipline `data_quality.py` already applies. Add a dedicated panel on the bank page. Acceptance: EVE and ΔNII are reported with explicit bucket-coarseness caveats, and the rate leg of the stress test can consume them.

### C6 — Replace flat loan-loss percentages with segment loss rates
> `stress.Shock.loan_loss_pct` applies one flat percentage to gross loans, ignoring the disjoint 8-category loan taxonomy the Gold layer already computes and validates. Apply per-category loss rates instead: land FDIC's published quarterly charge-off rates by loan category as a Bronze source, and let a scenario specify either a single blended rate (current behaviour, preserved) or per-category rates. Show the resulting loss decomposition by category. This makes a CRE-concentrated bank and a consumer-lender respond differently to the same "3% loan loss" scenario, which is the whole point of tracking concentration. Acceptance: two banks with identical gross loans and different loan mixes produce materially different losses under the same scenario, and the decomposition is rendered.

### C7 — Document or improve the single-representative-bond limitation
> `quantlib_pricing.loss_from_reprice` models each securities book as one representative bond. That limitation is documented in the module docstring but is invisible to a user comparing the two pricing engines on `/stress-lab`. Surface it in the comparison panel's caption. If C4's per-bank duration work lands maturity buckets, upgrade the QuantLib path to price a small ladder rather than a single bond and report the difference. Acceptance: no user can read the QuantLib-vs-linear comparison without seeing what the QuantLib model actually is.

### C8 — Add credit-quality trajectories
> NPL, net charge-offs, allowance coverage and Texas Ratio are all single-quarter snapshots today. Using the landed quarterly history (and much more of it after B1), compute per-bank trajectories: NPL trend and acceleration, NCO trend, allowance-coverage direction, and a simple deterioration flag when several move adversely together. Add them to the Gold layer so every consumer gets them, and surface them on the credit page and the bank page. Acceptance: the credit page can rank by deterioration, not only by level.

### C9 — Validate the M&A weights and add a pro-forma calculator
> `ma_fit.DEFAULT_WEIGHTS` (`funding .45, business .25, size .15, geo .15`) are hand-set and never tested against a single real transaction. Using the deal history landed in B6, evaluate whether the fit score ranks actual acquirers above non-acquirers, and refit the weights if it does not — publishing either result. Separately, add a pro-forma calculator: for a (target, acquirer) pair compute combined assets, combined CET1, goodwill created, tangible-book-value dilution and earn-back period, plus the **combined** county-level HHI using the existing `footprint.county_concentration`, flagging every county that would cross the Fed's 1800 screening threshold. Acceptance: selecting a candidate on the bank page opens a pro-forma view, and the weight validation result is published on `/model` or a new governance page.

### C10 — Add market-implied risk metrics
> Landed Tiingo OHLCV is used only to draw a candlestick. Compute and expose, per bank with a matched ticker: beta and correlation versus a regional-bank benchmark, realised volatility versus peer median, maximum drawdown, and — joined to Gold — price-to-tangible-book and price-to-earnings. Then do the thing that makes this valuable: measure whether banks the X-Ray flags as high risk subsequently underperform. That is the cheapest genuine validation available for the rule engine, and the result is worth publishing either way. Acceptance: a new market panel on the bank page, and a published correlation between X-Ray severity and forward equity returns with its sample size and significance.

### C11 — Add conditional peer percentiles
> `peers.add_percentile_ranks` ranks every bank against the entire population, so a $1.2B bank is ranked against a $200B bank and the result is partly a size percentile in disguise. Add size-bucket-conditional and cluster-conditional percentile ranks alongside the existing global ones (`percentile_rank_<metric>_within_size`, `_within_cluster`), computed in the same single pass so the "build Gold once" contract holds. Let the UI switch between the three bases, and default the X-Ray's peer context to the conditional one. Acceptance: a bank's percentile visibly differs across the three bases, and every percentile display states which basis it uses.

### C12 — Make filing-diff z-scores robust to small samples
> `filing_diff.diff` computes z-scores from at most 7 historical observations, and its materiality floors (`2.0%` / `0.3pp`) are absolute constants that do not scale with the bank. Add a minimum-observations gate below which a z-score is reported as `None` with a stated reason rather than computed from a 2-sample standard deviation; report `n` alongside every z so a user can weigh it; and scale the materiality floor relative to the item's own typical magnitude for that bank. B1's backfill will materially improve this — run it first and re-measure. Acceptance: every flag carries its sample size, and no flag is produced from fewer observations than the configured minimum.

### C13 — Control for multiple testing across the population
> `filing_diff` applies a `z >= 2.0` threshold to 13 tracked line items across 1,049 banks each quarter, which produces on the order of 2,700 flags by chance alone. Add population-level context: report the expected false-positive count for the current threshold, and offer a Benjamini–Hochberg FDR-controlled flag set as an alternative to the raw threshold. Surface the choice in the UI on `/filing-diff` and `/briefing`. Acceptance: a user can see how many of the flags shown are expected to be noise, and can switch to an FDR-controlled view.

### C14 — Build a backtest harness
> **Nothing in this product has ever been backtested** — not the deposit-flight score, not the X-Ray flags, not the filing-diff flags, not the M&A weights. Build a harness in `pipelines/transforms/` that, for a given signal at quarter *t*, measures outcomes at *t+1…t+k* across the landed history: did flagged banks subsequently show deposit outflows, capital deterioration, credit deterioration, cluster migration, or (where B6 is landed) failure/acquisition? Report hit rate, lift over base rate, and confidence intervals. Publish the results on a new `/backtest` governance page **including negative results** — "no detectable signal at this horizon with this sample" is a more credible statement than silence. Run B1 first so there is enough history to test. Acceptance: every headline signal has a published, dated backtest with its sample size.

### C15 — Handle FDIC's year-to-date annualised ratios correctly
> FDIC's NIM, ROA, ROE and efficiency ratios are year-to-date annualised, so a Q1 value and a Q4 value are not comparable — yet `/trends` plots them as a continuous line and `get_bank_trends` returns them without qualification. Compute quarterly-isolated versions from the YTD deltas where the inputs allow, add them to Gold as distinct fields, and either plot those on `/trends` or mark the YTD series explicitly on the axis. The one caption on `MetricGroupPage` that mentions this is not sufficient given how many surfaces consume these fields. Acceptance: no chart plots YTD-annualised ratios across quarters without either converting them or labelling the axis.

## D · Product and workflow gaps

### D1 — Add export everywhere
> There is no CSV, Excel, PDF or chart-data export anywhere in the product, which disqualifies it from any analyst workflow. Add: (a) a reusable "Download CSV" control on every table (screener, earnings, credit, funding, compare, heatmap, distributions, stress-lab results, county concentration); (b) a "download chart data" action on every chart; (c) a server-side per-bank PDF tearsheet covering profile, X-Ray, capital, concentration, peer cluster, risk score and stress results. Every export must embed the data vintage, the source attribution, and the G7 disclaimer, and must respect the G3 licensing check for Tiingo-derived fields. Acceptance: every table and chart is exportable, and no export omits vintage, source or disclaimer.

### D2 — Add saved screens, watchlist notes and threshold alerts
> The watchlist is a bare list of certs with no notes and no alerting, and the quarterly briefing is a page users must remember to visit. Extend the watchlist schema in `libs/python/banklens_common/src/banklens_common/db.py` with free-text notes and per-metric threshold rules ("uninsured deposits move more than 3pp", "X-Ray severity increases", "enters the top-25 risk leaderboard"). Add saved screener definitions. Add an evaluation stage to the existing orchestration DAG that checks every rule after a refresh and writes triggered alerts, surfaced in-app and optionally by email. Acceptance: a user can save a screen, set a threshold on a watched bank, and see a triggered alert after a data refresh.

### D3 — Add a global quarter selector
> 21 of 23 pages are silently locked to the latest landed quarter even though `data.population(repdte)` already accepts a quarter argument and 8 quarters are landed. Add a global quarter context in the frontend, persisted in the URL, plus a `quarter` query parameter on every population-scoped bridge route, threaded through to the tools. Show the selected quarter prominently on every page. Where a page genuinely cannot be time-shifted (branch map, county HHI — annual SOD only), disable the control with an explanation rather than silently ignoring it. Acceptance: changing the quarter changes every population-scoped page, and time-invariant pages say why they do not move.

### D4 — Add holding-company roll-up views
> Depends on B4. Once FR Y-9C data is landed, add a HoldCo entity to the model with a parent/subsidiary tree, and let a bank page roll up to its holding company — showing consolidated financials, the list of subsidiary charters, and which figures are charter-level versus consolidated. Match tickers to the HoldCo, since that is the entity the market prices, and correct the current crosswalk behaviour accordingly. Acceptance: a multi-charter holding company renders as one entity with its charters listed, and the price chart is attached to the entity the ticker actually represents.

### D5 — Add a custom peer-set builder
> Peer grouping today is limited to k-means clusters and size buckets, but every analyst covers a hand-picked universe. Add named, persisted peer sets (same storage pattern as the watchlist): create from search, from a screener result, from a cluster, or from an M&A candidate list. Make every population-scoped page able to filter to the active peer set, and add peer-set-conditional percentiles (see C11). Acceptance: a user creates a 14-bank peer set and every population page, chart and percentile respects it.

### D6 — Make the compare page arbitrary and visual

> `BANKLENS_AUTH_ENABLED=false` disables authentication and authorization entirely, and the bridge sends `Access-Control-Allow-Headers: *`. Both are documented and deliberate for local dev, but one env var separates a deployment from an open service. Make the bridge refuse to start with auth disabled unless it is also bound to a loopback address, and log a prominent warning on every request in that mode. Narrow the allowed headers to the set actually used (`Authorization`, `Content-Type`). Acceptance: an auth-disabled bridge bound to `0.0.0.0` fails to start with a clear message.

### G6 — Add secrets management to the Kubernetes manifests
> `platform/k8s/` contains no `Secret`, no SealedSecret and no ExternalSecret; credentials exist only as `.env` files intended for local Docker Compose. Add proper `Secret` references for the database credentials, the OIDC client secret and any API keys, with a documented provisioning path (SealedSecrets or External Secrets Operator), and update the deployments to consume them via `envFrom`/`secretKeyRef`. Ensure no secret value is ever committed and that `kubectl kustomize` still validates in CI. Acceptance: every credential the deployments need comes from a `Secret`, and the manifests contain no plaintext values.

### G7 — Add disclaimers to the product
> The application renders a deposit-flight risk score as a coloured percentage next to real, named, operating banks, alongside capital-adequacy verdicts and merger-concentration screens, with **no statement anywhere** that this is not investment advice, not a supervisory rating, not a regulatory capital calculation, and not a prediction of failure. Add: a persistent footer disclaimer in `NavShell`; a first-run acknowledgement modal; contextual notes on `/model`, `/stress-lab` and the bank-page risk panel; and the same disclaimer text embedded in every export produced by D1. Keep the wording precise and consistent with what the code actually claims — the docstrings' "structural resemblance, not a prediction" framing is already correct and should be the source. Acceptance: no view or export presenting a risk figure lacks a disclaimer.

### G8 — Make model cards immutable and versioned
> `deposit_flight.save_card()` overwrites `ml/deposit_flight/model_card.json` in place, so a retrain silently replaces the model that produced every previously shown score, and nothing recorded which card was used. Make cards content-addressed: write to `ml/deposit_flight/cards/<hash>.json`, keep a `current` pointer, retain history, and record the card hash on every scored result returned by `get_risk_score`, `get_risk_leaderboard`, `get_model_card` and the briefing's risk-entrant calculation. Show the card version in the UI and allow `/model` to display a historical card. Acceptance: a score shown to a user can be reproduced exactly after any number of subsequent retrains.

### G9 — Surface provenance end to end
> Every Bronze partition carries a `_provenance.json` with the source URL, fetch timestamp and content checksum, and none of it ever reaches a user — so the product's central claim ("every number traces back to a real, publicly available source") is architecturally true and practically unverifiable by anyone using it. Build the path: propagate the originating Bronze partition and checksum through Silver and Gold, expose it via the `/api/metric-lineage` route from D9, and render a "verify this number" affordance that shows the source URL, the fetch timestamp, the checksum and the exact source field names. This is the single highest-leverage credibility feature in the entire backlog — it converts the project's best architectural decision into a visible product differentiator. Acceptance: any number in the UI can be traced to a source URL and a verifiable checksum without leaving the app.
